The API in plain English — and the one rule that keeps automations honest

You’ve been using Claude through a chat window. You type, Claude responds, you read it. That’s the front end. The API is the back end — a way for other software to talk to Claude directly, without you in the middle. A new enquiry form comes in, Claude drafts a response. An email lands in a Gmail label, Claude summarises the thread. A spreadsheet updates, Claude generates the weekly report. All of it happens in the background, driven by events — not by you sitting at a keyboard.

You don’t need to write code. Three no-code tools — Zapier, Make, and n8n — do the wiring for you through a visual interface. Zapier is gentlest, Make is more flexible, n8n is open-source and the most technical of the three. You can run a real automation through Claude Sonnet for roughly a fraction of a cent per run. The setup time, not the API bill, is the real investment.

The “do it manually first” rule

Automate only what you have already done repeatedly by hand, and know works. If you haven’t manually responded to twenty enquiries and developed a sense of what good looks like, you can’t configure Claude to produce good automated outputs at scale. You’ll build an automation that produces mediocre work — and you won’t notice, because you’re no longer in the loop. Before you automate any task, ask yourself three questions:

The three-question readiness test
  1. Have I done this task manually at least ten to twenty times?
  2. Do I have a clear sense of what a good output looks like — could I write the standard down?
  3. Would I be comfortable reviewing weekly rather than every time?

If the answer to any of those is no, the task is not ready to automate. Keep doing it manually. Keep refining your prompt. The automation comes later.
